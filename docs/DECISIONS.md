# Decisions: Android, iOS 1.7 parity

This logs the Android-side decisions for bringing Ferry Messenger for Android to iOS 1.7 parity (newest at the bottom).
The iOS repo's `docs/DECISIONS.md` and `PLAN-android.md` hold the earlier ones.

| ID | Date | Decision | Why | Revisit when |
|---|---|---|---|---|
| D1 | 2026-11-16 | Engine pin `70aa388` (iOS main, v1.7); `go.mod` toolchain `go1.27.3`; `build-engine.sh` checks the Go version with `GOTOOLCHAIN=local` | Android's rule: pin what the user merged; no silent toolchain download | the next engine change |
| D2 | 2026-11-16 | Reaction log entries don't notify (`Timeline.notifiable`), but still make the chat unread and move it up | Android never notified reactions; iOS 1.6 said reactions don't notify; no withdraw logic needed | users ask for reaction notifications (then also withdraw on removal) |
| D3 | 2026-11-16 | Swipe to reply start→end (right in LTR), mirrored in RTL; iOS swipes left | Android messaging convention; ours (right side) are then away from the back-gesture edge | user feedback |
| D4 | 2026-11-16 | Camera: "Take Photo" and "Record Video" via the system camera (`TakePicture`/`CaptureVideo`, FileProvider `cache/camera`), no CAMERA permission, no library | Android has no single photo-or-video intent; no permission prompt | a camera library is approved |
| D5 | 2026-11-16 | Paste: the platform's own (field toolbar, keyboard insertion; `image/*`, `video/*`), no Paste chip; keyboard GIFs/stickers allowed | the Android way to paste; the keyboard's service, not Ferry's | users miss iOS's chip |
| D6 | 2026-11-16 | A per-chat sequential send order; video preparation one at a time; media first, then the text | Instagram's web send takes one attachment; MediaCodec limits | – |
| D7 | 2026-11-16 | `PickMultipleVisualMedia` with ordered selection (exists in activity 1.13.0, verified) | the platform picker, no permission | – |
| D8 | 2026-11-16 | TalkBack sender label on bubbles, with the time (iOS `spoken`/`SpokenSender`) | a pre-1.6 parity gap | – |
| D9 | 2026-11-16 | No new dependencies | the user approves each library | – |
| D10 | 2026-11-16 | Testing on the demo only; live items listed for the user | the user is asleep; no Instagram actions | – |
| D11 | 2026-11-16 | 1.7 release APK signed with a Mac-held key outside the repo, no minification, install guide | friends install by hand; JNI names | Play Store or CI signing |
| A12 | 2026-11-16 | **All** sends of a chat (texts, media, voice, retries) share one serial queue, so a text after a set waits for it; iOS sends the text at once | makes "then your text" true; a text alone with nothing queued goes as fast as today | texts feel slow behind big uploads; or iOS settles A§6.3 the other way |
| A13 | 2026-11-16 | Photo preparation one at a time (a single executor), not concurrent as on iOS | ten 2048 px decodes at once ≈ 250 MB on 2–4 GB phones | never needed faster |
| A14 | 2026-11-16 | Swipe: 60 dp threshold, 1/3 past it, 2:1 horizontal rule after the touch slop, claimed in the Main pass (children and the list first), consumed in the Initial pass after; arrow from the leading side at offset − 40 dp; `GestureThresholdActivate` haptic; no `systemGestureExclusion` (the edge's back gesture wins) | iOS's numbers; Compose's pass order gives the voice seek and the scroll priority and cancels the long press | real-phone feel |
| A15 | 2026-11-16 | Day chip: a surface capsule with a 2 dp shadow (no glass on Android), `labelMedium` semibold; never the incoming bubble grey | iOS's design review; the app's JumpButton/header convention | design pass |
| A16 | 2026-11-16 | The bubble clock follows the phone's 12/24-hour setting; day labels use the locale's best patterns ("EEEdMMM", wide weekday) | as the inbox does (`rememberTimeFormats`) | – |
| A17 | 2026-11-16 | Time inline via a transparent run + overlay (text); a dark capsule on cards; on the bubble's last part (a share's text) | WhatsApp's/iOS's layout | – |
| A18 | 2026-11-16 | One TalkBack description per bubble on `MessageMenu`'s node; links and Reply as custom actions; a media bubble reads "From Kivo, Photo, 9:41" (iOS: "From Kivo: Photo, 9:41") | Compose merges parent then child descriptions; avoids reading the time twice | a TalkBack user's feedback |
| A19 | 2026-11-16 | Link detector: http(s), `www.`, bare domains only with a short fixed TLD list | no TLD database without a library; NSDataDetector has one | missed or false links reported |
| A20 | 2026-11-16 | Mark as Unread swipe colour iOS's `swipeUnread` (#48484A / #636366, white content); icons `mark_email_unread` / `drafts` | neutral, set apart from Archive; colour means account | design pass |
| A21 | 2026-11-16 | `+` is a Material DropdownMenu: Take Photo, Record Video, Choose from Library (iOS order), camera items only with `FEATURE_CAMERA_ANY`; no camera app → "No camera app on this phone." | as iOS's menu; no `<queries>` needed for a launch | – |
| A22 | 2026-11-16 | One `PickMultipleVisualMedia(10)` launcher with the request's `maxItems` = slots left; the single picker for one slot; extras dropped with iOS's message | verified API: max = min(contract, request), must be ≥ 2 | – |
| A23 | 2026-11-16 | Pasted/inserted videos are copied into `cache/outgoing` before they queue | a clip's or IME's read grant may end before a queued transcode starts | – |
| A24 | 2026-11-16 | Demo switches named after iOS's: `--ei group_older`, `--ei group_extra`, `--ez reaction`, `--ez clipboard` | one vocabulary across both repos | – |
| A25 | 2026-11-16 | `versionCode` 17 for 1.7, +1 per release | sideloaded updates need a growing code | Play Store |
| A26 | 2026-11-16 | Reaction pills in a custom `Layout`: measured unconstrained, never sizing the bubble, placed by iOS's `PillPlacement`; drop 22 dp; group spacing 10/1 | the Box widened our short bubble; iOS's squeeze trap | FOLLOWUPS #59/#60/#62 on iOS |
| A27 | 2026-11-16 | The floating day shows only after a user drag, hides 1 s after the scroll stops, 200 ms fade | iOS; programmatic scrolls make no drag interaction | – |
| A28 | 2026-11-16 | Mark-unread swipe starts inside the row; no edge exclusion on the inbox | the left edge is back (leaves the app from the root) | real-phone feel |
| A29 | 2026-11-16 | `AppModel.apply` clears a chat's notification on Instagram's counts, not `isUnread` | a chat marked unread here would keep a stale notification | – |
| A30 | 2026-11-17 | `Links.find` trims sentence punctuation and an unbalanced `)`, applies the not-after-a-word lookbehind to `www.` too, and drops a match that is only "www." | NSDataDetector does the same; a plain pattern needs it spelled out | missed or false links reported (with A19) |
| A31 | 2026-11-17 | `Timeline.spokenLabel` follows iOS's `spoken` literally: in a group an unsent tombstone is "text, time", not "From <name>, …" (the tombstone's text names its sender) | a line-for-line port | – |
| A32 | 2026-11-17 | Demo: Ada Lind (Tamo, read) and Ravi Shah (Kivo, unread) are always there; Ada's "today" starts at 00:01 and runs 4 minutes apart, so before 01:00 some of it is in the future; `--ei group_extra n` makes the group's unread 1 + n (iOS keeps 1) | the plan's data in every `--ez demo true` run; unread matches what the line shows | the demo is used around midnight |
| A33 | 2026-11-17 | `LoginFailed` only clears `running` (iOS's port); no changelog line claims the app reloads by itself after a resnapshot | the engine's own re-login after a resnapshot can't be reached on the demo; the plan's wording promised more than the code does | the live check of the resnapshot (PLAN §8.2) |
| A34 | 2026-11-17 | Links: the plan's fallback B. Underlined with a plain style; a text with links takes its own touches (`detectTapGestures`: a tap on a link opens it, else the bubble's tap; hold and double tap call `MessageMenu`'s through `TapTarget`); no `LinkAnnotation` | on the emulator a hold on a `LinkAnnotation` link opened the link and never the sheet (its clickable consumes the down, so the bubble's long press never starts) | Compose's links get a long-press hook |
| A35 | 2026-11-17 | Card times: a video's length moves to the bottom start (the time has the bottom end); a voice note shows its time under its length, not on a capsule | the corner capsule covered both (seen on the emulator; iOS draws it the same way) | iOS changes its cards |
| A36 | 2026-11-17 | Item 13: besides re-placing the line when a page moves it (the plan), the open doesn't let go of the line while the first row loaded is already unread and the chat's start isn't here | otherwise the quarter-screen rule let go at once on a five-message mailbox copy and the chat opened at the end (seen on the emulator) | – |
| A37 | 2026-11-17 | Demo: Ada Lind's "today" runs 4 minutes apart, closer after midnight (a 16th of the time since), so it's never in the future (replaces A32's first part) | the demo is used around midnight | – |
| A38 | 2026-11-17 | What floats over the thread (day chips, the floating day, the jump button) is `Bubbles.raised`: white in light, #3A3A3C in dark | the surface was black on black and a shadow doesn't show on black (tester R1-F7); lighter than the incoming bubble (#262629), never an account's colour | design pass |
| A39 | 2026-11-17 | A Room is observable: `Room.Version`, read by every accessor and bumped by every change, is snapshot state in the app (`AppModel` installs it; the model and its tests keep a plain count) | Compose's strong skipping (on by default, its opt-out removed in Kotlin 2.4) compares an unstable parameter by identity, so a composable handed the same mutated Room was skipped: inbox rows kept their old preview and dot after a live update, demo and engine alike (R1-F2). One fix for every screen; iOS's Room is `@Observable` | – |
| A40 | 2026-11-17 | A busy chat opening on a mailbox copy stays hidden while its line waits for the last message read (up to the existing 1 s), so the line moves once at most, not three times; a page landing after that second still moves it once | the simple fix; holding the reveal longer would go past iOS's "1 s at most" (R1-F3) | users notice the one move |
| A41 | 2026-11-17 | In a failed ("Not sent") bubble a tap on a link opens the link; elsewhere on the bubble a tap retries, and the "Not sent. Tap to retry." line retries | iOS: a link takes its own tap, and only the line retries (`MessageViews.swift` `statusLine`); Android's tap-anywhere retry is its own, from A4 (R1-F6) | – |
| A42 | 2026-11-17 | The floating day sits over the thread's top row with no backdrop (the content scrolls under it) | as iOS's floating chip; it shows only while the user scrolls | – |
| A43 | 2026-11-17 | A card's time never covers its own words: beside a placeholder's label, a link preview's title and site, a post's caption, a pile's count; on the last card of an opened set; the capsule over a picture only | R1-F4, R1-F5 (Elena's "Photo", the site at font scale 1.3) | – |
| A44 | 2026-11-17 | Swipe to reply (beyond A14): the touch slop is per axis (the larger of across and down), not the distance; a touch held past the long press (0.3 s) before it moves that far stays a hold; the arrow is drawn by the swipe's own modifier and grows 0.7 → 1 in 150 ms past the threshold, so a swipe recomposes nothing; TalkBack's "Reply" comes before the links' actions | the voice bars' seek counts its slop across only, so with the distance a slightly diagonal drag on them could become a swipe before the seek saw it (reasoned from the pass order: the demo's voice note can't load, so its seek can't be tried); without the hold rule a hold whose sheet opened, then dragged sideways, would also reply; iOS's 0.15 s growth | real-phone feel |
| A45 | 2026-11-17 | A chat marked unread here stays marked until it's opened or marked read: a newer message doesn't clear the mark, and removing an account keeps its marks (hidden with its chats), as iOS. Mark as Read/Unread is in General and Archived too, never on a request or a chat Instagram has unread | iOS 1.7's rules (`markRead` is its only clear); a newer message makes the chat unread by Instagram's count anyway, and opening it clears both | users expect a new message to replace the mark |
| A46 | 2026-11-17 | Pasted and keyboard-inserted photos are copied in at once too, not only videos (A23), each on its own thread the moment it arrives; then prepared from the copy, which goes once prepared. Only `content:` URIs whose provider says `image/*` or `video/*` are taken; anything else (a `file:` path included) is left to the field | photo preparation is now one at a time (A13), so a pasted photo can wait behind others as long as a video would, and its read grant may end first | users paste many large files |
| A47 | 2026-11-17 | In the demo every send still goes through the chat's send line and takes 0.6 s before "Not sent", so a set shows its order; demo transaction IDs carry a counter (several sends share a millisecond) | the demo sends nothing, but the order is what's under test; same-millisecond IDs collided in the thread's list | – |
| A48 | 2026-11-17 | What waits above the field goes with the thread (its prepared files deleted); what was sent stays on the chat's send line after leaving the thread or the app, and only a process that dies loses it, as a single send before | iOS keeps attachments per thread view too; the send line is the app's, not the screen's | users lose picks by leaving a chat |
| A49 | 2026-11-17 | Demo: our "Yes! Brunch at 11?" to Noor is 10 minutes old (iOS's demo has 25), so Edit can be checked on the demo | no demo message of ours was within Edit's 15 minutes, so the composer's Edit (prefilled, cursor at the end) couldn't be tried | – |
| A50 | 2026-11-17 | A thread's saved state is keyed by its room at the root (`key(roomID)` around the whole thread), so the draft, the camera's file, the launchers' pending results and the list's place can only be restored into the chat they came from, after a recreation or a process death | R2-F1: `rememberSaveable(roomID, …)` takes the room as an input, not the key, so a recreated activity restored Jonas's draft into the next chat opened (Ada), where Send would have gone to the wrong person | – |
| A51 | 2026-11-17 | `MainActivity` handles orientation, screen size and layout, dark mode (`uiMode`), keyboard, navigation, density and font scale itself (`configChanges`); Compose redraws, and the system bars' light/dark icons are set again in `onConfigurationChanged`. A process death or a language change still recreates it and returns to the inbox. Landscape with the keyboard up leaves no room for the field when a reply and a set wait above it | any recreation returned to the inbox and lost the draft, the reply and the waiting photos (R2-F2); the screen stack isn't saved. Checked: rotation, dark mode and font scale 1.3 keep the chat, the draft, the reply and the set, with the theme, text size and status-bar icons updated | a saved navigation stack; a landscape layout |
| A52 | 2026-11-17 | Leaving a chat drops its unsent draft (it survives HOME and coming back), as on iOS, whose `ThreadView` keeps it in `@State`, and as Android did before | R2-F3: the brief expected per-chat drafts; nothing had said otherwise | testers ask for per-chat drafts (a map in `AppModel`) |
